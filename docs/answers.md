# Ответы на теоретические вопросы ЛР1

Примеры взяты из кода этой работы: `ClientShort` и `Client`.

## 1. Что такое класс, что такое объект, как создать объект класса?

**Класс** — шаблон (тип), который описывает данные (поля) и поведение (методы) объектов.
В Python класс сам является объектом типа `type`.

**Объект (экземпляр)** — конкретная сущность, созданная по классу, со своими значениями полей.
`Client` — класс, а «Иванов Иван, тел. +79161234567» — его объект.

Объект создаётся вызовом класса как функции:

```python
c = Client(1, "Иванов", "Иван", "Иванович", "г. Москва, ул. Ленина, 1", "+79161234567", None)
```

## 2. В чём заключается принцип инкапсуляции? Как получить доступ к полям объекта из внешнего класса?

**Инкапсуляция** — объединение данных и методов работы с ними в одном классе и сокрытие
внутреннего состояния. Объект сам отвечает за корректность своих данных, а внешний код
работает с ним только через открытый интерфейс.

В Python нет модификаторов `private`/`public`, есть соглашения:

* `_name` — защищённый член («для своих и наследников»), это только соглашение;
* `__name` — приватный член: Python переименовывает его в `_ИмяКласса__name`
  (name mangling), поэтому `obj.__name` снаружи даёт `AttributeError`.

Доступ снаружи даём через **свойства** (`@property`): геттер возвращает значение,
сеттер проверяет новое значение перед записью.

```python
c.phone                 # геттер -> "+79161234567"
c.phone = "89031112233" # сеттер -> validate_phone -> "+79031112233"
c.__phone               # AttributeError
```

## 3. Что такое конструктор, зачем он нужен, как описывается конструктор в произвольном классе?

**Конструктор** — метод, который вызывается при создании объекта и приводит его
в корректное начальное состояние: задаёт поля и проверяет их.

В Python роль конструктора играет `__init__(self, ...)`. Первый параметр `self` —
уже созданный, но ещё не заполненный объект. В Python нет перегрузки по сигнатуре,
поэтому «перегрузку» делают через `*args, **kwargs` и проверку типов аргументов
(как в `ClientShort.__init__`: поля, словарь, JSON, строка через `;`) или через
альтернативные конструкторы `@classmethod`.

## 4. Опишите механизм создания объекта

Вызов `Client(...)` запускает метод `type.__call__`, который:

1. вызывает `Client.__new__(Client, ...)`: выделяется память и создаётся пустой объект
   (обычно это `object.__new__`);
2. если `__new__` вернул объект этого класса, вызывает `obj.__init__(...)` — инициализацию полей;
3. возвращает готовый объект.

У нас `__init__` наследуется от `ClientShort`. Он разбирает аргументы и вызывает `self._fill(values)`.
Для объекта `Client` срабатывает переопределённый `Client._fill`: он сначала вызывает
`super()._fill` (общие поля), затем заполняет адрес и e-mail. Если какое-то поле не проходит
проверку, выбрасывается исключение и объект не возвращается.

## 5. Что такое метод класса (статический), в чём его отличие от метода объекта? Два практических примера

* **Метод объекта** получает `self` и работает с данными конкретного экземпляра.
* **Статический метод** (`@staticmethod`) не получает ни объекта, ни класса. Это функция,
  которая логически принадлежит классу, и её можно вызвать без объекта: `Client.validate_phone(...)`.
* **Метод класса** (`@classmethod`) получает класс `cls`. Его используют для альтернативных
  конструкторов и для логики, которая зависит от класса-наследника.

Когда метод класса необходим:

1. **Валидация до создания объекта.** `Client.validate_email("a@b.ru")` можно вызвать, например,
   при проверке формы ввода, когда объекта ещё нет. Проверка не зависит от конкретного клиента.
2. **Альтернативные конструкторы и разбор входных данных.** `_parse_string` — метод класса:
   он берёт список полей из `cls.FIELDS`, поэтому один и тот же код разбирает строку
   и для `ClientShort` (5 полей), и для `Client` (7 полей).

## 6. Опишите структуру классов вашего языка, как в неё вписывается написанный вами класс

В Python всё является объектом. Любой класс неявно наследуется от `object`, а сами классы —
объекты метакласса `type`. От `object` любой класс получает базовые методы:
`__init__`, `__str__`, `__repr__`, `__eq__`, `__hash__` и другие.

Наша иерархия:

```
object
  └── ClientShort   (краткие данные, всё общее)
        └── Client  (полные данные: + адрес, e-mail)
```

Порядок поиска методов (MRO): `Client → ClientShort → object`.

## 7. Принцип наследования, переопределение методов и способы вызова переопределённого метода

**Наследование** — создание класса на основе существующего: наследник получает все поля
и методы родителя и может добавить свои или изменить унаследованные. Так убирается повтор
кода: `Client` берёт у `ClientShort` конструктор, валидацию, общие поля и сравнение.

**Переопределение** — наследник объявляет метод с тем же именем. Например, `Client.__str__`
печатает полную карточку вместо краткой, а `Client._fill` дополнительно заполняет адрес и e-mail.

Вызвать версию родителя можно так:

* `super().метод(...)` — основной способ (`super()._fill(values)` в `Client`);
* `ClientShort.метод(self, ...)` — явный вызов через имя класса.

## 8. Принципы работы конструкторов для наследуемых классов

* Если наследник не объявляет `__init__`, используется `__init__` родителя.
  Так сделано у нас: `Client` получает перегруженный конструктор `ClientShort` целиком.
* Если наследник объявляет свой `__init__`, конструктор родителя **автоматически не вызывается**.
  Его нужно вызвать явно: `super().__init__(...)`, иначе поля родителя не будут заданы.
* Обычный порядок такой: сначала инициализируется часть родителя, потом своя.
  У нас это делает `_fill`: `super()._fill(values)`, затем свои поля.

## 9. Какие методы объекта обязательно есть у любого написанного вами класса, что они делают

Все они унаследованы от `object`, если их не переопределить:

| Метод | Что делает | У нас |
|---|---|---|
| `__new__` | создаёт объект | не переопределён |
| `__init__` | инициализирует поля | переопределён в `ClientShort` |
| `__str__` | строка для пользователя (`print`, `str()`) | краткий вывод в `ClientShort`, полный в `Client` |
| `__repr__` | отладочное представление | `Client(client_id=1, ...)` |
| `__eq__` / `__ne__` | сравнение `==` / `!=` (по умолчанию сравнивает адреса в памяти) | сравнение по всем полям |
| `__hash__` | хеш для `set`/`dict` | если определён `__eq__`, Python ставит `__hash__ = None`: изменяемый объект нельзя положить в `set` |
| `__class__`, `__dict__` | класс объекта и словарь его полей | `vars(c)` показывает «искажённые» приватные имена |
